Sharing

io.github.retronym.sharing.Sharing
object Sharing

Operations on state shared between threads, with evidence types that make the guarded state reachable only from inside them.

The state is shared only in Mode.Concurrent. In Mode.Batch it is touched by one thread, and every operation here is the plain code it wraps. Each operation that takes code to run is an inline def whose batch branch is that code as it was before concurrency: a call site compiles to a test of the given Mode (a final field of its owner) and the original expression, and allocates nothing. The concurrent branches call the ClaimRegistry, or take a monitor.

The owner of the state supplies two givens: the Mode, and a ClaimRegistry for the operations that claim.

Which operation, by what the state is

  • A lazy fact, computed once by one writer while other threads wait for it: once (a value read without a lock once it is there) or claim (anything else). A ClaimKind is given beside the key's class and, for re-entry, a BlackHole. The writer's state is reached through methods that take the claim's evidence, Holds[key.type].
  • A short critical section over a collection or a few fields: a Guard whose fields are Guarded, or serialised and locking on another object's monitor. The guarded state is reached with Monitor[lock.type].
  • A value paired with the stamp it was computed at: Stamped, one immutable object in one field.
  • Fields that a reader may see without a lock, published by one field: Published and its Payloads, written with release and read with acquire semantics. Array slots: Publish.

The registry's strategy is the owner's: a CoarseLock serialises the threads, PerKeyClaims lets them run in parallel with a claim per key. Concurrency picks the mode and the registry together.

Evidence

Guarded state is reachable only through methods that take an evidence parameter (a Holds or a Monitor, below), in the manner of Clang's thread-safety REQUIRES annotations. Only the operations here can make evidence, so touching the state outside the claim or the lock does not compile. At run time the evidence is one shared object, so it costs nothing.

import io.github.retronym.sharing.*

class Symbol(name: String)(using Mode, ClaimRegistry):
  private var myInfo: Info | Null = null

  // private to the writer: reachable only with the claim's evidence
  private def store(i: Info)(using Sharing.Holds[this.type]): Unit = myInfo = i

  def info: Info =
    Sharing.once(this)(myInfo):
      val i = computeInfo()
      store(i)
      i

object Symbol:
  given Sharing.ClaimKind[Symbol] = Sharing.ClaimKind(What("computing info", null), lockWhenSerialised = true)

Entered and left only with the claim's evidence. Whether this thread is inside needs none, since only its own store can make that true. A field of the object it is mixed into, so it allocates nothing.

final class ClaimKind[-K](val what: What, val lockWhenSerialised: Boolean)

How the claim on a key of type K is taken. A given for each kind of key, beside its class. It says

How the claim on a key of type K is taken. A given for each kind of key, beside its class. It says

  • what the holder is doing, as a What, for lock-wait reports; and
  • whether serialised threads take the coarse lock for the key (lockWhenSerialised = true), or need no claim, because their reads are serialised and the computation is not a completion (false).
object LazyRef:
  given Sharing.ClaimKind[LazyRef] = Sharing.ClaimKind(What("evaluating lazy reference", null), lockWhenSerialised = false)

Contravariant, so one given serves a class, its subclasses and the singleton types that claim infers (ClaimKind[LazyRef] &lt;: ClaimKind[r.type]), and one given for a union serves both (ClaimKind[A | B]). The given is found through the key's class (its companion or enclosing object), so a key with no kind is an error at the claim: "no Sharing.ClaimKind for ...".

object suppressions extends Sharing.Guard:
  private val bySource = guarded(mutable.LinkedHashMap.empty[SourceFile, ListBuffer[Suppression]])
  def addSuppression(sup: Suppression)(using Context): Unit =
    locked:
      bySource().getOrElseUpdate(sup.annotPos.source, ListBuffer.empty) += sup

sealed abstract class Holds[K]

Evidence that the code it is given to is the one writer of the lazy facts keyed by key: K: it runs in claim(key).

Evidence that the code it is given to is the one writer of the lazy facts keyed by key: K: it runs in claim(key).

A capability in the manner of Clang's REQUIRES: state that only the writer may touch is reachable only through a method that takes one, so a touch outside the claim does not compile. Only claim, once and unguarded make one. It is invariant in K, so the evidence for one key is not evidence for another. One instance serves every key, so a holder allocates nothing.

The writer's state is private, its writes behind methods that take the evidence:

private def set(ref: Type | Null, done: Boolean)(using Sharing.Holds[this.type]): Unit =
  myRef = ref
  computed = done

and set(...) outside Sharing.claim(this) or Sharing.once(this) is an error: "this code must run as the one writer of (LazyRef.this : LazyRef)". At run time the parameter is the one shared held object.

Type parameters

K

the key, usually a singleton type such as this.type

inline def claim[K <: AnyRef & Singleton, T](inline key: K, inline cycleSubject: AnyRef | Null = ...)(inline op: Holds[K] ?=> T)(using inline kind: ClaimKind[K])(using inline mode: Mode, inline registry: ClaimRegistry): T

Runs op as the one writer of the lazy facts keyed by key, with the evidence of it.

Runs op as the one writer of the lazy facts keyed by key, with the evidence of it.

In a concurrent mode this goes through the ClaimRegistry: the key's claim when threads are parallel, where a wait that would close a wait-for cycle is reported against cycleSubject; the coarse lock, or as is, when threads are serialised, as the key's ClaimKind says. In batch mode op runs as is. key, its kind, cycleSubject and the registry are evaluated only in a concurrent mode. cycleSubject defaults to the key.

// the scope's one writer
Sharing.claim(this)(inside(op))
// one key for every bring-forward, the cycle reported against the symbol
Sharing.claim(BringForward, symbol)(initial.bringForward().current)

The key is a stable path (this, a val, an object), whose singleton type is inferred as K. A call expands to

val h = held.asInstanceOf[Holds[K]]
if mode.concurrent then registry.claim(key, kind, cycleSubject, () => op(using h))
else op(using h)

Re-entry by the owner of a claim runs op at once: the owner's test for re-entering its own computation is op's (a BlackHole, or a sentinel in the state).

Value parameters

inline def once[K <: AnyRef & Singleton, T <: AnyRef](inline key: K, inline cycleSubject: AnyRef | Null = ...)(inline peek: T | Null)(inline compute: Holds[K] ?=> T)(using inline kind: ClaimKind[K])(using inline mode: Mode, inline registry: ClaimRegistry): T

A lazy fact keyed by key, computed once: the value peek finds, or, when it finds none, the value computed as the one writer of key (see claim).

A lazy fact keyed by key, computed once: the value peek finds, or, when it finds none, the value computed as the one writer of key (see claim).

peek is asked again inside the claim first, since another thread may have computed the value meanwhile. peek must find the value only once it is complete; compute stores it. Another thread waits for an owner's computation at the claim, so compute is entered again only by its owner, re-entering its own computation: that is the place for a cycle test. In batch mode this is peek ?: compute.

// `myRef` is null until the value is stored; `computed` is set when the computation starts
def ref(using Context): Type =
  Sharing.once(this)(myRef):
    if computed then throw CyclicReference(NoDenotation) // only the owner gets here again
    compute()
    myRef.nn

Expands to the double-checked computation

val v = peek
if v != null then v
else claim(key, cycleSubject):
  val v1 = peek
  if v1 != null then v1 else compute

so a hit is peek's reads and a null test, in every mode. peek reads without the claim, so what it reads must be published whole (a final-field structure, a volatile, a value stored after what it refers to).
