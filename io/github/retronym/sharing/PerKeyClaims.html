PerKeyClaims

io.github.retronym.sharing.PerKeyClaims
See thePerKeyClaims companion object
final class PerKeyClaims(currentClaimant: () => Claimant, cycles: CycleHandler) extends ClaimRegistry

A ClaimRegistry for parallel threads: a claim per key, so that work on different keys runs at once.

A claim is its claimant's: reentrant for that claimant, and every other claimant that needs the key waits until the owner releases it, then looks at what the key guards again (computed, or left computable by an owner that unwound).

A wait that would close a cycle in the wait-for graph (each waiting claimant records the claim it waits on, Claimant.waitingOn; following the owners from the claim leads back to the waiter) is a dependency cycle, handled as Claimant says. The check runs at every slice of a wait, since another claimant's wait may start after this one's.

the claimant of the calling thread

def claim[T](key: AnyRef, kind: ClaimKind[Nothing], cycleSubject: AnyRef, op: () => T): T

Runs op as the one writer of the lazy facts keyed by key: holding the claim on it, or the coarse lock if kind says serialised threads take it, or as is if they need no claim. Re-entry by the holder runs op at once.
