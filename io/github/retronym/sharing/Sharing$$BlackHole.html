BlackHole

io.github.retronym.sharing.Sharing.BlackHole
trait BlackHole

The black hole of a computation that the holder of the claim on this object runs: which thread is inside it.

Entered and left only with the claim's evidence. Whether this thread is inside needs none, since only its own store can make that true. A field of the object it is mixed into, so it allocates nothing.

private abstract class InheritedCacheImpl(...) extends InheritedCache, Sharing.BlackHole
// inside `Sharing.claim(this)`: a re-entry by the owner is a cycle
val computed = computeInside(throw CyclicReference(clsd))(clsd.computeBaseData(using this, ctx))
// from any thread: an invalidation from inside the computation is ignored
if valid && !isInsideHere then ...

inside(op) expands to val was = insideThread; insideThread = currentThread; try op finally insideThread = was, and computeInside(onCycle)(op) to if insideThread != null then onCycle else inside(op).

final inline protected def computeInside[T](inline onCycle: => Nothing)(inline op: T)(using Holds[this.type]): T

Runs op as the one computation this black hole guards. It is entered by the holder of the claim, the only thread that can be inside, so finding some thread inside is the holder re-entering its own computation: a cycle, and onCycle is evaluated.

Runs op as the one computation this black hole guards. It is entered by the holder of the claim, the only thread that can be inside, so finding some thread inside is the holder re-entering its own computation: a cycle, and onCycle is evaluated.

However op ends, it leaves: a computation that unwinds (a cancellation, a back-off, a crash) leaves what it guards computable by the next caller. A hand-written "started" flag must remember to do that.

Value parameters

onCycle

what to do if the computation is entered again by its owner; does not return
