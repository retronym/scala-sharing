Stamped

io.github.retronym.sharing.Stamped
See theStamped companion object
final class Stamped[+K, +T](val stamp: Int, val value: T)

A value with the stamp it was computed at, as one immutable object, held in one var of the cache's owner.

Bloch's racy single-check idiom (Effective Java, Item 83) over an immutable holder (JCIP §3.4.2): a reader that misses computes and stores, and two may both compute; the holder's final fields (JLS §17.5) make that safe without a volatile.

A stamp says what the value was computed against: a generation of the inputs, a run, a version. The value is valid while its stamp is the current one.

Both fields are final, so a reader that loads the reference sees the pair whole, however it was published: no fences, no test of a Mode, and the same code with one thread or several. A writer replaces the stamped value. A reader can never see a current stamp with an older value, nor a stamp and a value from two writers. The price is an allocation per miss and a dependent load per hit (the owner's field, then the stamped value's).

sealed trait PerGeneration // the kind of stamp: a phantom type

class Library(using Stamp[PerGeneration]):
  private var exports: Stamped[PerGeneration, List[String]] = Stamped.Empty
  def exportedNames: List[String] =
    exports.cached:
      computeExports()

A stamp is an Int, never 0 for a current one: Stamped.Empty, what a field starts with, has stamp 0. K is the stamp's kind, a phantom type: the operations take the current stamp of that kind as a given Stamp[K], which the owner supplies (typically an inline given that reads a counter). A call site therefore names no stamp, and a field is never read with one kind of stamp and written with another.
